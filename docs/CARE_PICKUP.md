# 배려 픽업 MVP — 현재 소스

이 문서는 현재 소스의 기능을 설명합니다. `release/Pleos-CurbLink-demo.apk`, `captures/`, 기존 시연 대본과 검증 결과는 v0.1-demo 자료입니다. 새 APK를 게시하기 전에는 해당 화면이나 17개 시험 통과 기록을 배려 픽업의 실행·검증 증거로 사용하지 않습니다. 릴리즈 바이너리와 캡처는 변경하지 않았습니다. 이번 변경의 빌드/시험 실행은 코디네이터 담당입니다.

## 서비스 요청과 상태

정차(P단·차속 0·UX 제한 해제) 중 고객이 차량 안에서 수령, 트렁크 적재 도움, 준비 시간 여유를 각각 선택하거나 해제합니다. 기본값은 모두 해제이며 일반 픽업에는 추가 수락/준비 확인을 요구하지 않습니다. 진단, 장애 여부, 증빙, 자유 입력 의료 정보는 수집하지 않습니다. 선택값은 메모리의 시연 상태이며 초기화하면 제거됩니다.

요청이 있으면 고객 화면에 `매장 응답 대기 · 지원 미확정`, `매장 수락`, `매장 거절 · 인계 보류`를 텍스트로 표시합니다. 매장 상품 READY 이벤트와 배려 요청 수락은 별개입니다. 운영자 패널은 요청 항목을 보여주고 ACCEPTED/DECLINED를 모의 입력합니다. 거절 시 자동으로 일반 픽업으로 전환하지 않습니다. 고객이 정차 중 요청을 해제하거나 매장이 다시 수락한 뒤 고객 준비를 재확인해야 합니다.

## 준비와 승인

배려 요청에는 매장 수락 이후 고객의 `정차 중 · 인계 준비됐어요` 터치가 필요합니다. 도착/구역 확인/매장 상품 준비 완료/직원 OTP 인증은 고객 준비 확인을 대신하지 않습니다. 준비 확인과 최종 개방 요청 승인은 별도 동작입니다. 큰 버튼(최소 높이 64dp), 20sp 상태·조작 글자와 선택됨/선택 안 함 텍스트를 사용하며 색상만으로 상태를 전달하지 않습니다. 실제 음성 기능 없이 정차 중 터치로 전체 배려 요청 흐름을 조작합니다.

관련 선택 변경은 수락 상태를 PENDING으로 되돌리고 고객 준비를 해제합니다. 같은 선택값 유지 시에는 초기화하지 않습니다. 매장 거절, 구역 확인 해제, P단 이탈, 이동, UX 제한 또는 차량 데이터 만료는 준비 확인을 해제합니다. 안전 상태 복귀나 재수락만으로 준비 상태가 복구되지 않습니다. 개방 진행 중에는 고객 요청 변경과 준비 확인을 차단합니다. 개방 요청 후 매장이 거절하면 모의 열림 응답도 차단하며 시간 초과 후 직원 재인증과 고객 준비 재확인이 필요합니다.

최종 승인 순간에 기존 차량 최신성·차속·P단·UX·센서 최신성·장애물·직원 OTP·OEM 허용·구역 확인·닫힌 테일게이트·READY 주문·명시적 승인을 다시 평가하고, 배려 요청에는 수락/고객 준비 조건을 추가합니다. 모의 열림 응답에도 배려 조건을 재확인합니다. 실제 Pleos/Gleo/CarPay/UWB/SVM 또는 차량 제어·출금은 없습니다.

## 소스 기준 시연과 검증

1. 새 소스 빌드에서 정차 중 서비스 항목을 선택합니다. 응답 대기에서 지원 미확정 표시와 개방 차단을 확인합니다.
2. 모의 결제, 운영자 패널의 매장 준비 완료/구역 확인, 직원 코드 발급·인증을 진행합니다. 도착과 OTP만으로 준비 완료되지 않는지 확인합니다.
3. 매장 거절을 입력해 인계 보류를 확인합니다. 수락으로 바꾼 뒤에도 고객 준비 확인 전에는 차단되어야 합니다.
4. 고객 준비 버튼을 누르고 기존 안전 조건을 충족한 뒤 별도 개방 승인을 합니다.
5. 승인 전 선택 변경, 매장 거절, D단 전환 후 P단 복귀, UX 제한 후 해제를 각각 시험합니다. 준비를 다시 확인해야 하며 선택 변경 시 매장 재수락도 필요합니다.
6. 모두 미선택한 초기 상태에서는 기존 일반 픽업 시나리오가 그대로 동작해야 합니다.

`DomainTest.kt`의 기존 17개 테스트를 보존하고 일반 픽업, 각 서비스의 대기/수락/거절, 고객 준비, 선택 변경, 안전 상태 변경 및 기존 게이트 유지 테스트 7개를 추가했습니다. 실행 결과를 주장하지 않습니다. 코디네이터는 JDK17/Gradle8.9/SDK35에서 `compileDebugUnitTestKotlin`과 `run-domain-tests.ps1`의 JUnitCore 경로로 검증해야 합니다(Windows Gradle 테스트 워커 파이프 문제).
