# 0.5.2 프리뷰 — main 반영 및 최신 캡처

2026-10-31 KST (10월30일 작업에서 이어짐). 사용자 요청: 현재 구현을 main에 반영하고, 네 활성 브랜치 README를 최신 APK·시뮬레이션 캡처로 갱신한다.

## 반영 범위

- 0.5.1 위의 차선 준비·추천 안정성·관측 기반 이유, 이용 불가 하차 지점/대안/새 승인, 실패 후 주문·사진 보존과 다음 행동 안내.
- `versionCode 8`, `0.5.2-arrival-preview`. 기존 모든 배포 APK와 목업 HTML은 보존한다.
- 브라우저의 도로 캔버스와 옆 패널 사이 높이 증가 순환 수정.
- 실행/빌드/소스 포장 스크립트의 APK 경로를 0.5.2로 갱신. 런처는 부팅/설치 실패 시 중단한다.
- ADB 연결이 불안정했던 PC의 시험 캡처 내보내기에 명시적 localhost와 foreground user 실패 검사를 적용했다.
- `scripts/verify-simulation.py`: 여섯 웹 여정을 실제 UI로 완료하고 PNG/해시를 수집한다.
- 후진 장면은 R단 상태를 확인하고 재생을 멈춰 촬영한다. 네이티브 PixelCopy는 Compose 프레임 제출을 기다려 탭 전환 직전 화면을 잘못 수집하지 않도록 했다.
- `main`/`integration`/`simulation`/`apk`의 README는 같은 최신 갤러리를 사용하고 각 브랜치의 역할만 구분한다. 하위 README와 인수인계에도 최신 자료 진입점을 제공한다.

## 검증과 원본

- Android 빌드·시험 컴파일·JUnit80·lint(오류0/기존 의존성 경고3), 제품 APK 경계·v2 서명·16KB 정렬.
- Pleos 2.1.0의 외부 시험 드라이버 18흐름/94조건과 실제 CarService/NaviHelper 서비스 연결·재연결 16조건.
- 브라우저 도로 시뮬레이터의 픽업·주차·잠시 정차·식사·한강 인계·배리어프리 여섯 여정 완료. 음식 수령/하차 승인은 명시적으로 조작하며, 운전자 터치 주문과 안전 확인 전 하차 승인이 차단됨을 확인했다. 페이지 오류 없음.
- 웹 하차 대안·후보 없음·새 승인 및 840/480 폭 복구 화면 확인.
- [게시 APK·검증 집계](../release/VERIFICATION-0.5.2.json), [네이티브 PNG 원본과 해시](../captures/android/0.5.2/verification.json), [웹 PNG9장·여정 결과·해시](../captures/web/0.5.2/verification.json).
- 시험 전 앱 기록을 로컬 work/에 보존하고 종료 후 바이트 일치로 복원한다. 인증정보·개인 백업·SDK/AVD·빌드 캐시는 게시하지 않는다.

## 증거의 한계

CarService/NaviHelper는 에뮬레이터의 실제 서비스 IPC다. 외부 시험 차선 입력, 견본 매장/시설/주문, 웹 합성 카메라는 실제 제공자 연동과 구분한다. 이번 플랫폼 시험의 일치하는 활성 목적지 경로는 확인되지 않았으며 `routeReady=false`다.

브라우저 검증은 Chromium 소프트웨어 렌더링이다. APK 실행이나 물리 GPU·실차 주행 검증을 대체하지 않는다. 실제 음성/TTS, 사진 선택기 취소와 공유 대상 전달, TalkBack/로터리, 좁은 native 창/글자 확대, 공식 폼팩터 및 실차 검증은 남아 있다. 웹-APK 실시간 상태 동기화도 미구현이다.

이번 main 반영은 사용자의 명시적 요청에 따른 프리뷰 게시이며, 자동 main 승격이나 최종 적합 인증이 아니다. 강제 푸시·브랜치 삭제·기기 데이터 초기화는 하지 않는다.
